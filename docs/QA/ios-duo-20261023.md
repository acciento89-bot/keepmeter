# KeepMeter 1.1.0 (6): native Duo continuity

## Reproduced issue and change

On the retained iPhone Duo / iOS 27.1, open Add Purchase, enter text with the software keyboard, unfold, partially fold, fully close and cancel the sheet. Build 5 preserves the draft and keyboard but loses the `topBarTrailing` add action after dismissal. Native XCTest and the actual Device Hub accessibility tree confirm the action is absent; switching tabs restores it.

Build 6 places the same `presentAddPurchase()` action in a persistent bottom safe-area inset and removes the duplicate empty-state action. The existing free-limit/paywall gate, purchase data, reminders and billing behavior are unchanged. Existing receipt/category/search/CSV features remain part of version 1.1.0. Android is unchanged.

## Provider and evidence isolation

Every native QA launch explicitly sets `--keepMeterProviderDisabledQA`. DEBUG-only early exits prevent all real StoreKit initialization, entitlement reconciliation, unfinished-transaction handling, purchase and restore entry points; they never unlock Pro. The actual EntitlementStore compiled against a synthetic StoreKit module fails before the guards and passes afterward. Normal DEBUG and Release behavior remains enabled against that synthetic provider; after removing DEBUG blocks, EntitlementStore release tokens match the previous shipping source.

No real test purchases, redemptions, restores, reconciliation or advertising transactions were performed. Provider tests do not claim native StoreKit runtime validation.

XCUIScreen.main captures the now-inactive outer display during unfolding and can produce black screenshots. Such frames are not accepted as expanded visual proof or Store images; use the actual active internal display capture. Private acceptance fixtures and failure screenshots remain outside the public report. This document is not evidence of an Apple upload, submission or approval.
